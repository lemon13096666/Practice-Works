Создание инсталляторов и развертывание ПО

Полное практическое руководство: от сборки нативного приложения C++ в режиме Release до генерации MSI-пакета с иконками, каталогом справок и верификацией на виртуальной машине.

Теоретические основы Windows Installer

Технология Windows Installer (MSI) — это компонент операционной системы Windows, обеспечивающий структурированный процесс установки, обслуживания и удаления программного обеспечения. В отличие от простых скриптовых архиваторов, MSI использует транзакционную реляционную модель.

Транзакционность

Если во время установки возникает ошибка, система выполняет полный Rollback (откат к исходному состоянию без мусорных файлов и битых ключей реестра).

Самовосстановление

Windows Installer отслеживает целостность ключевых файлов и при их непреднамеренном удалении автоматически доустанавливает недостающие компоненты.

ProductCode и UpgradeCode

Идентификация релизов через GUID. При смене номера версии инсталлятор производит чистое удаление предыдущего релиза (Major Upgrade).

1 Подготовка C++ приложения к дистрибуции

Для создания дистрибутива всегда используется конфигурация Release. Особое внимание для C++ нужно уделить параметрам рантайма, чтобы приложение запустилось на машине без установленной Visual Studio.

// main.cpp - Тестовое приложение для инсталляции
#include <iostream>
#include <fstream>
#include <string>
#include <windows.h>

int main() {
    SetConsoleOutputCP(CP_UTF8);
    std::cout << "========================================\n";
    std::cout << " Инженерное приложение v1.0.0 (C++)\n";
    std::cout << "========================================\n\n";
    // Проверяем файл справки из поддиректории "help"
    std::ifstream helpFile("help/manual.txt");
    if (helpFile.is_open()) {
        std::cout << "[OK] Файл документации обнаружен в подпапке help!\n";
        helpFile.close();
    } else {
        std::cout << "[ПРЕДУПРЕЖДЕНИЕ] Папка help не найдена по локальному пути.\n";
    }
    std::cout << "\nНажмите Enter для выхода...";
    std::cin.get();
    return 0;
}
Важный нюанс C++ (Static vs Dynamic Linking):
Если собирать проект со стандартным флагом /MD (Dynamic Runtime), целевая система потребует установленный Microsoft Visual C++ Redistributable. Чтобы приложение работало сразу «из коробки», перейдите в: Свойства проекта → C/C++ → Создание кода → Библиотека времени выполнения и установите Многопоточный (/MT) для конфигурации Release.

2 Добавление и настройка Setup Project

  1. Убедитесь, что установлено расширение Microsoft Visual Studio Installer Projects.
  2. Щелкните правой кнопкой мыши по решению в Solution Explorer → Добавить → Создать проект...
  3. Найдите шаблон Setup Project, назовите его, например, AppInstaller.
  4. Выделите созданный проект и в окне Properties (Свойства) настройте метаданные:
Свойство Пример значения Назначение
Author / Manufacturer StudentCorp Определяет папку установки: C:\Program Files (x86)\StudentCorp\...
ProductName DesktopApp C++ Название в списке «Установка и удаление программ».
InstallAllUsers True Установка программы для всех пользователей Windows.
TargetPlatform x64 (или x86) Разрядность целевой операционной системы.

3 Файловая структура, папка Help и ярлыки

В окне File System Editor определяются каталоги развертывания:

Создание подпапки help (Требование методички):

  • Щелкните правой кнопкой мыши по Application Folder → Add → Folder.
  • Назовите новую директорию help.
  • Внутри папки help нажмите Add → File... и выберите файл справки (например, manual.txt).

Иконка и ярлык на Рабочем столе:

  1. В Application Folder добавьте исполняемый файл приложения (Primary Output или прямо .exe) и файл app_icon.ico.
  2. Правой кнопкой мыши по exe-файлу → Create Shortcut to...
  3. Переименуйте ярлык (например, Мое C++ Приложение).
  4. В свойствах ярлыка найдите пункт Icon → Browse... → выберите загруженную иконку app_icon.ico.
  5. Перетащите готовый ярлык в левую папку User's Desktop (и при необходимости в User's Programs Menu).

4 Тестирование на виртуальной машине (VirtualBox)

Тестирование инсталляторов на «чистой» виртуальной ОС позволяет выявить отсутствие динамических библиотек (DLL) и скрытых зависимостей.

Чек-лист проверки установки:

  • Установщик .msi успешно запускается без ошибок UAC/прав.
  • Файлы развернулись в C:\Program Files (x86)\....
  • Создана директория help с документацией.
  • На Рабочем столе отображается ярлык с вашей иконкой.
  • Приложение запускается и находит файл справки.

Чек-лист проверки удаления:

  • В панели «Программы и компоненты» отображается правильная иконка и имя издателя.
  • При вызове «Удалить» процесс деинсталляции проходит чисто.
  • Ярлык с Рабочего стола и рабочая папка в Program Files бесследно удалены.
